# Views, Templates, Components & Vite Assets

RocketPHP includes a compiled Blade-inspired template engine ([`ViewEngine`](../src/View/ViewEngine.php) + [`Compiler`](../src/View/Compiler.php)), reusable `<x-...>` components, and Vite integration.

---

## 1. View Directory & File Extensions

Views live in `resources/views/`. When calling `view('users.profile', $data)`, [`ViewEngine::resolvePath()`](../src/View/ViewEngine.php) searches registered paths in order for these extensions:
1. `.rocket.php` *(recommended)*
2. `.blade.php`
3. `.php`
4. `.html`

Compiled PHP templates are cached to `storage/cache/views/{sha1($path)}.php` and automatically recompiled whenever `filemtime($source) > filemtime($compiled)`.

### Namespaced Views
Register additional view roots (e.g., from a ServiceProvider):
```php
use Rocket\Facades\View;

View::addPath(base_path_or_dir, 'admin');
// Render via:
return view('admin::dashboard');
```
*(Note: there is no `base_path()` global helper; use `app()->basePath(...)`.)*

## 2. Rendering & Passing Data

```php
// Global helper (returns Rocket\Http\Response):
return view('welcome', ['name' => 'RocketPHP']);

// Inside a Controller:
return $this->view('users.show', ['user' => $user]);

// Raw HTML string via Facade:
$html = \Rocket\Facades\View::render('emails.welcome', ['name' => 'Alice']);

// Global data shared across all views:
\Rocket\Facades\View::share('appName', config('app.name'));
```

## 3. Supported Template Syntax (`Compiler::compileString()`)

| Feature | RocketPHP Syntax | Compiled Behavior |
| :--- | :--- | :--- |
| **Comments** | `{{-- hidden comment --}}` | Stripped at compile time |
| **Escaped Output** | `{{ $var }}` | Calls `e($var)` (`htmlspecialchars` with `ENT_QUOTES \| ENT_SUBSTITUTE`, UTF-8; bypasses escaping for `HtmlableInterface`) |
| **Raw Output** | `{!! $html !!}` | `<?= $html ?>` (unescaped — only use for trusted HTML) |
| **Layouts** | `@extends('layouts.app')` | Renders parent layout after child evaluation |
| **Sections** | `@section('content') ... @endsection` | Captures output buffer into `$sections['content']` |
| **Yielding** | `@yield('content', 'Default')` | Outputs captured section or fallback |
| **Partials** | `@include('partials.nav', ['active' => 'home'])` | Calls `$this->renderPartial(..., $__data)` |
| **CSRF Input** | `@csrf` | `<?= csrf_field(); ?>` |
| **Method Spoof** | `@method('PUT')` | `<?= method_field('PUT'); ?>` |
| **Vite Assets** | `@vite(['resources/css/app.css'])` | `<?= vite(...); ?>` |
| **Conditionals** | `@if(...)`, `@elseif(...)`, `@else`, `@endif`, `@unless(...)`/`@endunless`, `@isset(...)`/`@endisset`, `@empty(...)`/`@endempty` | Native PHP control blocks |
| **Loops** | `@foreach(...)`/`@endforeach`, `@for(...)`/`@endfor`, `@while(...)`/`@endwhile` | Native PHP loops |
| **Raw PHP** | `@php ... @endphp` | `<?php ... ?>` |
| **Component Props** | `@props(['type' => 'info', 'title' => null])` | Calls `$this->extractProps(...)` and strips props from `$attributes` |
| **Custom Directives** | `app('view.compiler')->directive('name', fn ($args) => ...)` | Replaced during compilation |

> **Important:** Directives not listed above (such as `@forelse`, `@switch`, `@auth`, `@guest`, `@error`, `@push`/`@stack`, `@once`, `@class`) are **not** implemented in `Compiler.php`.

## 4. Template Inheritance & Layouts Example

`resources/views/layouts/app.rocket.php`:
```html
<!DOCTYPE html>
<html lang="en">
<head>
    <title>@yield('title', 'RocketPHP App')</title>
    @vite(['resources/css/app.css', 'resources/js/app.js'])
</head>
<body>
    @include('partials.header')
    <main>@yield('content')</main>
</body>
</html>
```

`resources/views/home.rocket.php`:
```html
@extends('layouts.app')

@section('title')Home Page@endsection

@section('content')
    <h1>Welcome, {{ $username }}</h1>
@endsection
```

## 5. View Components (`<x-...>`)

RocketPHP supports both **Anonymous Components** and **Class-Based Components**.

### Resolution Order (`ViewEngine::resolveAndRenderComponent`)
When encountering `<x-foo.bar-baz ...>`:
1. Checks explicit aliases registered via `$viewEngine->component('foo.bar-baz', ...)`.
2. Checks class `App\View\Components\Foo\BarBaz` extending `Rocket\View\Component`.
3. Falls back to anonymous view `components.foo.bar-baz` (`resources/views/components/foo/bar-baz.rocket.php`).
4. Falls back to direct view `foo.bar-baz`.
5. Otherwise throws `InvalidArgumentException`.

### Anonymous Components
Create `resources/views/components/alert.rocket.php`:
```html
@props(['type' => 'info', 'title' => null])

<div {{ $attributes->merge(['class' => 'alert alert-' . $type]) }}>
    @if($title)
        <strong>{{ $title }}</strong>
    @endif
    {{ $slot }}
</div>
```

Use in templates:
```html
<!-- Plain attributes, bound PHP expressions (:prop), boolean flags -->
<x-alert type="danger" :title="$heading" dismissible id="err-1" class="mt-4">
    Something failed!
</x-alert>

<!-- Self-closing -->
<x-alert type="success" title="Saved!" />
```
- `::class="foo"` passes a literal `:class="foo"` string attribute (escaped colon).
- `:count="5 + 2"` evaluates PHP expression `(5 + 2)`.

### Class-Based Components
Scaffold with CLI:
```bash
php rocket make:component UserBadge
# Or inline HTML without view file:
php rocket make:component UserBadge --inline
# Or anonymous template only:
php rocket make:component alert --view
```

Class [`Rocket\View\Component`](../src/View/Component.php) exposes `$attributes` (`ComponentAttributeBag`), `$slot` (`ComponentSlot`), `shouldRender(): bool`, and extracts public non-static properties & public methods via `data()`. Constructor arguments are matched against camelCase, kebab-case, or snake_case attributes, with container DI fallback for class-typed dependencies.

### Named Slots & `ComponentAttributeBag`
```html
<x-card>
    <x-slot:header class="font-bold">Profile</x-slot:header>
    Body content here
    <x-slot name="footer"><button>Save</button></x-slot>
</x-card>
```
Inside `components/card.rocket.php`:
- `$slot` and named slots (`$header`, `$footer`) are instances of [`ComponentSlot`](../src/View/ComponentSlot.php) (`toHtml()`, `isEmpty()`, `isNotEmpty()`, `hasActualContent()`, `$attributes`).
- [`ComponentAttributeBag`](../src/View/ComponentAttributeBag.php) methods: `get($key, $default)`, `has($key)`, `first()`, `only(...)`, `except(...)`, `merge(array $defaults)`, `class(array|string $classes)`, `filter(callable)`, `whereStartsWith($prefix)`, `whereDoesntStartWith($prefix)`, `all()`, `toHtml()`.
- Both `ComponentAttributeBag` and `ComponentSlot` implement [`HtmlableInterface`](../src/View/Contracts/HtmlableInterface.php), so `{{ $attributes }}` and `{{ $slot }}` output HTML without double-escaping.

## 6. CSRF & Method Spoofing in Forms

```html
    @csrf
    @method('PUT')
    <input type="text" name="title" value="{{ $post->title }}">
    <button type="submit">Update</button>
</form>
```

## 7. Asset Management (Vite & Public Storage)

### Vite (`Rocket\Foundation\Vite` + `vite.config.js`)
- **Dev HMR**: `npm run dev` writes `public/hot` with the dev server URL; `@vite(['resources/css/app.css', 'resources/js/app.js'])` emits `@vite/client` and dev asset tags.
- **Production**: `npm run build` compiles to `public/build/` with `public/build/manifest.json`; `@vite(...)` emits versioned `/build/assets/...` tags.
- **Individual Asset URL**: `{{ \Rocket\Facades\Vite::asset('resources/images/logo.svg') }}`.

### Public Storage Assets
Files in `storage/public/` linked via `php rocket storage:link` to `public/storage` can be referenced with:
```html
<img src="{{ asset('storage/avatars/user.png') }}" alt="Avatar">
```
