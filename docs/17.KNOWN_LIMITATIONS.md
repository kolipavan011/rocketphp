# Known Limitations & Missing Features

This file documents verified architectural gaps, unfinished edge cases, and unsupported features discovered in the RocketPHP source code. **Do not assume any of these work until verified or implemented in `app/`.**

---

## 1. Missing Subsystems (Not Implemented in Core)

- **Authentication & Authorization**: No `auth()` helper, no guard/user provider, no password reset, no RBAC/permissions/gates/policies (`app/Http/Middleware/AuthMiddleware.php` is a blank stub).
- **Logging Subsystem**: No `Logger` class, PSR-3 implementation, `Log` facade, or automatic file logging to `storage/logs/`.
- **Event Dispatcher / Hooks**: No event bus, listeners, subscribers, or model lifecycle hooks (`creating`, `saved`, etc.).
- **Plugin System**: Removed intentionally in favor of Service Providers (`plugins/`, `Rocket\Plugin\*`, `make:plugin`, `plugin:*` do not exist).
- **Database Seeders & Rollbacks**: No `db:seed`, no `Seeder` base class, and no `migrate:rollback` / `migrate:fresh` command (`Migrator` only exposes `run()`).
- **Queue / Mail / Notifications / Scheduler**: No background job queues, mailers, or task scheduler.
- **PSR-7 / PSR-15 Adapters**: `Request`, `Response`, and `MiddlewareInterface` use custom RocketPHP classes rather than `Psr\Http\Message\*` or `Psr\Http\Server\*`.

## 2. Verified Implementation Limitations & Quirks

### Bootstrap & Caching
1. **`CacheServiceProvider` Not Registered by Default**: [`Rocket\Cache\CacheServiceProvider`](../src/Cache/CacheServiceProvider.php) is omitted from both [`bootstrap/app.php`](../bootstrap/app.php) and [`config/app.php`](../config/app.php). Calling `Cache::*` without registering it throws `NotFoundException: Target class [cache] does not exist`.
2. **Cache Drivers**: `CacheManager` only supports `'array'` and `'file'`. Redis, Memcached, and APCu are not implemented.
3. **`config:cache` & `route:cache` Not Auto-Loaded**: Both CLI commands generate `bootstrap/cache/config.php` and `bootstrap/cache/routes.php`, respectively, but `Kernel::bootstrap()`, `Application::bootstrapConfig()`, and `RouteServiceProvider::boot()` do **not** read those cache files automatically. Also `route:cache` fails if any route uses a Closure (since `var_export()` cannot export Closures).
4. **CLI Provider Loading**: `Console\Application::run()` calls `$this->app->boot()` directly instead of `Kernel::bootstrap()`, so providers listed only in `config/app.php` (not in `bootstrap/app.php`) are not registered during CLI execution.

### Routing & Controllers
5. **`Router::prefix()` Quirk**: Calling `Route::prefix('admin')` pushes onto `$this->groupStack` without popping and returns `$this` (`Router`). Chaining `->group(fn () => ...)` onto it fails because `Router::group()` expects `(array $attributes, Closure $routes)`. Always use `Route::group(['prefix' => 'admin'], ...)`.
6. **No Route Model Binding**: Parameters like `{user}` pass raw string values; you must call `User::findOrFail($id)` manually.
7. **Invokable Controller Class String**: Passing `MyController::class` alone to `Route::get()` fails in `Container::call()`. Pass `[MyController::class, '__invoke']`.
8. **No Global `route()` or `env()` Helpers**: Use `Route::url('name', $params)` and `Rocket\Foundation\Env::get('KEY', $default)`.

### Security, Sessions & Validation
9. **Empty Default Middleware Stack**: `Kernel::$middleware`, `$middlewareGroups`, and `$routeMiddleware` start empty. `VerifyCsrfToken`, `SecureHeaders`, and `ThrottleRequests` do **not** run until explicitly wired.
10. **In-Memory `SessionManager`**: `SessionManager` stores data only in `$this->attributes` on the instance. It does **not** read/write PHP `$_SESSION`, cookies, files, or database — session state and CSRF tokens do not persist across separate PHP-FPM HTTP requests unless custom persistence is implemented.
11. **In-Memory `RateLimiter`**: `RateLimiter::$storage` is a static array (`self::$storage`), so rate limits reset across new PHP-FPM processes and are not shared across multiple servers/workers.
12. **File Uploads**: `Request::file($key)` returns raw `$_FILES[$key]` arrays; no `UploadedFile` abstraction or file validation rules (`file`, `mimes`, `image`, `max_kb`) exist in `Validator`.
13. **Validation Failure Behavior**: `Kernel::handleException()` catches `ValidationException` and returns status `422` without `errors` array in JSON or redirect-with-errors in HTML unless caught explicitly by your controller/middleware.

### Database & ORM
14. **PostgreSQL Identifier Quoting**: `Query\Builder` and `Schema\Blueprint` wrap table/column names in backticks (`` ` ``), which is valid in MySQL/MariaDB/SQLite but invalid SQL syntax in PostgreSQL.
15. **`ModelBuilder::withTrashed()` & `onlyTrashed()`**: `ModelBuilder::__construct()` adds `WHERE deleted_at IS NULL` to `$this->query`. Currently `withTrashed()` does not remove that `whereNull` clause, and `onlyTrashed()` adds `WHERE deleted_at IS NOT NULL` alongside it (producing an unsatisfiable query). Use `$model->newQuery(withSoftDeletes: true)` when you need soft-deleted records.
16. **Schema Alterations & Relationships**: No `Schema::table()` (`ALTER TABLE`), no `belongsToMany` / polymorphic relations, no nested eager loading (`with('a.b')`), and `Builder::$havings` is unused (`having()` is not implemented).
17. **Naive Model Pluralization**: `Model::getTable()` unconditionally appends `'s'` to the snake-case short class name (`Category` -> `categorys`). Set `protected ?string $table` explicitly when needed.

### Views
18. **Subset of Blade Directives**: Only `@props`, `<x-...>`, `<x-slot>`, `{{ }}`, `{!! !!}`, `{{-- --}}`, `@extends`, `@section`, `@endsection`, `@yield`, `@include`, `@csrf`, `@method`, `@vite`, `@if`/`@elseif`/`@else`/`@endif`, `@unless`/`@endunless`, `@isset`/`@endisset`, `@empty`/`@endempty`, `@foreach`/`@endforeach`, `@for`/`@endfor`, `@while`/`@endwhile`, `@php`/`@endphp`, and custom directives are compiled.
19. **Layout Section Persistence**: `ViewEngine` resets `$sections` and `$componentStack` only when a top-level `render()` finishes without `@extends`. If an uncaught exception is thrown mid-render inside a long-lived worker, ensure views clean up cleanly (output buffers are cleaned in `evaluatePath()`).
