# Middleware (`Rocket\Http\Pipeline`)

HTTP middleware intercepts requests before they reach route handlers and can inspect or modify responses on the way back out using an onion-style pipeline ([`src/Http/Pipeline.php`](../src/Http/Pipeline.php)).

---

## 1. Middleware Contract

Every middleware class must implement [`Rocket\Http\Contracts\MiddlewareInterface`](../src/Http/Contracts/MiddlewareInterface.php) (or expose a `handle(Request $request, Closure $next): Response` method / be a Closure):

```php
<?php

declare(strict_types=1);

namespace App\Http\Middleware;

use Closure;
use Rocket\Http\Contracts\MiddlewareInterface;
use Rocket\Http\Request;
use Rocket\Http\Response;

class AuthMiddleware implements MiddlewareInterface
{
    public function handle(Request $request, Closure $next): Response
    {
        // Pre-processing: reject early if unauthorized
        if (!$request->header('authorization')) {
            return new Response('Unauthorized', 401);
        }

        // Pass request deeper into pipeline / route action
        $response = $next($request);

        // Post-processing: modify outgoing response
        return $response->withHeader('X-Authenticated', 'true');
    }
}
```

Generate a middleware class with:
```bash
php rocket make:middleware ApiKeyMiddleware
```

---

## 2. Default Configuration State (Important!)

In [`Rocket\Foundation\Kernel`](../src/Foundation/Kernel.php):
- `$middleware = []` (Global middleware)
- `$middlewareGroups = ['web' => [], 'api' => []]`
- `$routeMiddleware = []` (Aliases)

**None of the built-in security middlewares (`VerifyCsrfToken`, `SecureHeaders`, `ThrottleRequests`) are enabled by default.** You must register them explicitly.

---

## 3. Registering Global, Group, and Aliased Middleware

Configure middleware on the `'kernel'` singleton in [`AppServiceProvider::boot()`](../app/Providers/AppServiceProvider.php) (or [`bootstrap/app.php`](../bootstrap/app.php)):

```php
<?php

declare(strict_types=1);

namespace App\Providers;

use App\Http\Middleware\AuthMiddleware;
use Rocket\Foundation\Kernel;
use Rocket\Foundation\ServiceProvider;
use Rocket\Security\Middleware\SecureHeaders;
use Rocket\Security\Middleware\ThrottleRequests;
use Rocket\Security\Middleware\VerifyCsrfToken;

class AppServiceProvider extends ServiceProvider
{
    public function boot(): void
    {
        /** @var Kernel $kernel */
        $kernel = $this->app->make('kernel');

        // 1. Global middleware (runs on EVERY HTTP request)
        $kernel->setMiddleware([
            SecureHeaders::class,
        ]);

        // 2. Middleware groups ('web' wraps routes/web.php; 'api' wraps routes/api.php)
        $kernel->setMiddlewareGroups([
            'web' => [
                VerifyCsrfToken::class,
            ],
            'api' => [
                ThrottleRequests::class,
            ],
        ]);

        // 3. Named route middleware aliases
        $kernel->setRouteMiddleware([
            'auth'     => AuthMiddleware::class,
            'csrf'     => VerifyCsrfToken::class,
            'throttle' => ThrottleRequests::class,
        ]);
    }
}
```

> **Warning:** `Kernel::setMiddleware()`, `setMiddlewareGroups()`, and `setRouteMiddleware()` **replace** the internal arrays rather than merging. Configure all groups/aliases in one place.

## 4. Assigning Route & Controller Middleware

### On Individual Routes or Groups
```php
use Rocket\Facades\Route;
use App\Http\Middleware\AuthMiddleware;

// Using registered alias or FQCN
Route::get('/dashboard', [DashboardController::class, 'index'])->middleware('auth');
Route::post('/webhooks/stripe', [WebhookController::class, 'handle'])->middleware(VerifySignatureMiddleware::class);

// Route group
Route::group(['prefix' => 'admin', 'middleware' => ['auth']], function () {
    Route::get('/users', [AdminUserController::class, 'index']);
});
```

### Inside Controllers
In [`Rocket\Routing\Controller`](../src/Routing/Controller.php), call `$this->middleware(string $middleware)` inside `__construct()` with optional `->only(...)` or `->except(...)`:

```php
class PostController extends Controller
{
    public function __construct()
    {
        $this->middleware('auth')->except('index', 'show');
        $this->middleware('throttle')->only('store');
    }
}
```

---

## 5. Execution Order & Pipeline Mechanics

When a request enters `Kernel::handle(Request $request)`:
1. **Global Pipeline**: `Kernel::$middleware` runs first in declaration order.
2. **Routing**: `Router::dispatch($request)` matches the route and resolves controller middleware (if applicable).
3. **Route Pipeline**: `Router::resolveRouteMiddlewares()` expands group names (`'web'`, `'api'`) and aliases (`'auth'`), then merges `$route->getMiddleware()` followed by `$controller->getMiddlewareForMethod($method)`.
4. **Action Execution**: The route Closure or Controller method runs via `Container::call()`.
5. **Response Unwinding**: Post-processing runs in reverse order back out through route/controller middleware, then global middleware.

`Pipeline::resolvePipe()` resolves string middleware names through `$this->container->make($pipe)`, so middleware constructors automatically receive DI dependencies (e.g., `VerifyCsrfToken` receives `CsrfTokenManagerContract`).
