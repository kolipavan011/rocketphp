# Extensibility & Service Providers (and Plugin Status)

> **Important Notice on Plugins:** RocketPHP does **not** have a plugin system. Any legacy `plugins/` directory, `Rocket\Plugin\*` classes, `plugin.json` manifests, and `make:plugin` / `plugin:*` CLI commands were removed and do **not** exist in the codebase. Instead, RocketPHP uses **Service Providers** as its primary architecture for modularity and extension.

---

## 1. Service Provider Architecture (`Rocket\Foundation\ServiceProvider`)

Every framework subsystem (`RouteServiceProvider`, `ViewServiceProvider`, `DatabaseServiceProvider`, `SecurityServiceProvider`, `CacheServiceProvider`) and application module extends [`Rocket\Foundation\ServiceProvider`](../src/Foundation/ServiceProvider.php):

```php
<?php

declare(strict_types=1);

namespace App\Providers;

use Rocket\Foundation\ServiceProvider;

class PaymentServiceProvider extends ServiceProvider
{
    public function register(): void
    {
        // Phase 1: Bind interfaces, singletons, or scoped services into $this->app
        $this->app->singleton(PaymentGateway::class, function ($app) {
            return new StripeGateway(config('services.stripe.key'));
        });
    }

    public function boot(): void
    {
        // Phase 2: Runs AFTER all providers have called register().
        // Safe to resolve other services, configure Kernel middleware,
        // add view paths/directives, or register routes.
    }
}
```

### Creating & Registering a Service Provider
1. Scaffold with CLI:
   ```bash
   php rocket make:provider PaymentServiceProvider
   ```
2. Register the provider class in **both**:
   - [`config/app.php`](../config/app.php) under `'providers'` (loaded by `Kernel::bootstrap()` for HTTP requests), **and**
   - [`bootstrap/app.php`](../bootstrap/app.php) via `$app->register(new PaymentServiceProvider($app))` if the provider is also needed in CLI commands (`Console\Application::run()` calls `$app->boot()`, not `Kernel::bootstrap()`).

`Application::register()` deduplicates by class name via `$this->loadedProviders`, so registering in both `bootstrap/app.php` and `config/app.php` runs `register()` and `boot()` only once.

## 2. All Available Extension Points in RocketPHP

Even without a plugin manager, you can cleanly extend RocketPHP in `app/` without editing `src/`:

| Extension Goal | Mechanism | Where to Implement |
| :--- | :--- | :--- |
| **Bind custom services / interfaces** | `$this->app->singleton(...)`, `bind(...)`, `scoped(...)`, `alias(...)` | `ServiceProvider::register()` |
| **Enable Cache subsystem** | Register `Rocket\Cache\CacheServiceProvider` | `config/app.php` / `bootstrap/app.php` |
| **Configure global/group/alias middleware** | `$kernel->setMiddleware()`, `setMiddlewareGroups()`, `setRouteMiddleware()` | `AppServiceProvider::boot()` |
| **Add custom View directives** | `$this->app->make('view.compiler')->directive('name', fn ($args) => ...)` | `AppServiceProvider::boot()` |
| **Add namespaced View directories** | `$this->app->make('view')->addPath($dir, 'namespace')` | `AppServiceProvider::boot()` |
| **Add reusable View Components** | `app/View/Components/*.php` or `resources/views/components/*.rocket.php` or `View::component('alias', Class::class)` | `app/View/Components/` or `ServiceProvider::boot()` |
| **Register modular route files** | `$router->group(['prefix' => 'admin'], fn () => require ...)` | `ServiceProvider::boot()` |
| **Add custom CLI commands** | Classes in `app/Console/Commands/*.php` or `Console::command(...)` | `app/Console/Commands/` or `routes/console.php` |
| **Add static helper Facades** | Extend `Rocket\Facades\Facade` and implement `getFacadeAccessor()` | `app/Facades/` |
| **Custom Cache Store driver** | Implement `Rocket\Cache\Contracts\CacheStoreInterface` | Custom subclass of `CacheManager` or container binding |

---

## 3. Unavailable Extension Features (Not Implemented)

- **Plugin System**: No `PluginInterface`, `PluginManager`, `plugins/` directory, or dynamic plugin discovery/enable/disable.
- **Events & Hooks**: No `EventDispatcher`, listeners, observers, or model lifecycle hooks (`creating`, `created`, etc.).
- **Package Auto-Discovery**: Composer packages are not auto-discovered via `extra.rocket.providers`; register providers explicitly.
