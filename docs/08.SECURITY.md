# Security Architecture & Audit (`Rocket\Security`)

This document describes every security feature verified in the RocketPHP source code and explicitly separates **what RocketPHP implements**, **what the application developer must wire/implement**, and **security limitations**.

---

## 1. Security Features Implemented in RocketPHP Core

| Feature | Source Implementation | Verified Mechanism & Details |
| :--- | :--- | :--- |
| **Password Hashing** | [`Rocket\Security\Hasher`](../src/Security/Hasher.php) (`'security.hasher'`) | Prefers `PASSWORD_ARGON2ID` after running `testArgonSupport()` self-test; falls back to `PASSWORD_BCRYPT` when host CRT lacks working Argon2id (e.g., Windows MSVC PHP 8.2). Exposes `make()`, `check()`, `needsRehash()`. |
| **Authenticated Encryption** | [`Rocket\Security\Encrypter`](../src/Security/Encrypter.php) (`'security.encrypter'`) | AES-256-GCM (`aes-256-gcm`) using 12-byte `random_bytes()` IV and 16-byte AEAD authentication tag. Requires exact 32-byte key (supports `base64:` prefix from `config('app.key')`). |
| **CSRF Protection** | [`CsrfTokenManager`](../src/Security/CsrfTokenManager.php) & [`VerifyCsrfToken`](../src/Security/Middleware/VerifyCsrfToken.php) | Generates 64-char hex token (`bin2hex(random_bytes(32))`), validates with constant-time `hash_equals()`. Checks `_token` input, `X-CSRF-TOKEN`, or `X-XSRF-TOKEN` header. Returns HTTP `419`. Allows URI exclusions via `$except` property. |
| **Secure HTTP Headers** | [`SecureHeaders`](../src/Security/Middleware/SecureHeaders.php) | Injects `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `X-XSS-Protection: 1; mode=block`, `Referrer-Policy: strict-origin-when-cross-origin`, `Content-Security-Policy`, plus `Strict-Transport-Security` (`max-age=31536000; includeSubDomains`) when `$request->isSecure()`. |
| **Rate Limiting** | [`RateLimiter`](../src/Security/RateLimiter.php) & [`ThrottleRequests`](../src/Security/Middleware/ThrottleRequests.php) | Fixed-window counter keyed by `sha1("throttle:{$ip}:{$path}")`. Default 60 attempts / 1 min. Returns HTTP `429` with `Retry-After` and `X-RateLimit-*` headers. |
| **SQL Injection Defense** | [`Connection`](../src/Database/Connection.php) & [`Query\Builder`](../src/Database/Query/Builder.php) | Uses PDO with `PDO::ATTR_EMULATE_PREPARES => false` and typed `bindValue()` (`INT`, `BOOL`, `NULL`, `STR`) for all Builder values. Raw SQL requires explicit `Rocket\Database\Raw` / `DB::raw()`. |
| **Mass Assignment Guard** | [`Model`](../src/Database/ORM/Model.php) | `$guarded = ['*']` and `$fillable = []` by default, preventing unintended mass-assignment via `fill()` / `create()`. |
| **XSS Prevention** | [`View\Compiler`](../src/View/Compiler.php) & `e()` in [`helpers.php`](../src/Foundation/helpers.php) | `{{ $var }}` compiles to `<?= e($var) ?>` which calls `htmlspecialchars(..., ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8')` unless object implements `HtmlableInterface`. |
| **Input Validation** | [`Validator`](../src/Security/Validation/Validator.php) & [`ValidationException`](../src/Security/Validation/ValidationException.php) | Rules: `required`, `email`, `numeric`, `integer`, `min`, `max`, `in`, `same`, `alpha`. Throws `ValidationException` (HTTP `422`). |
| **Production Error Suppression** | [`Kernel::handleException()`](../src/Foundation/Kernel.php) | When `Application::isProduction()` (`APP_ENV === 'production'`) and status is `500`, hides exception class, message, file, line, and stack trace. |

## 2. Features Requiring Developer Implementation / Wiring

Do **not** assume these are active automatically:

1. **Middleware Activation**: `VerifyCsrfToken`, `SecureHeaders`, and `ThrottleRequests` are **not** attached to `Kernel` out of the box. You must register them in `AppServiceProvider::boot()` via `$kernel->setMiddleware(...)` / `setMiddlewareGroups(...)` (see [`07.MIDDLEWARE.md`](07.MIDDLEWARE.md)).
2. **Persistent Sessions**: [`SessionManager`](../src/Security/Session/SessionManager.php) stores attributes only in a PHP object array (`protected array $attributes = []`). It does **not** persist across HTTP requests via `$_SESSION`, encrypted cookies, or database/file drivers. Implement persistent session storage or cookie-encrypted session middleware in `app/` before relying on session auth or cross-request CSRF tokens.
3. **Authentication & Authorization**: There is **no** built-in auth system, login controller, `auth()` helper, RBAC, permissions, or password reset flow. [`app/Http/Middleware/AuthMiddleware.php`](../app/Http/Middleware/AuthMiddleware.php) is an empty scaffold. Implement authentication (session/JWT/token validation + `$request->setUser($user)`) and authorization checks in `app/`.
4. **File Upload Security & Path Traversal**: `Request::file($key)` returns the raw `$_FILES[$key]` array. RocketPHP has **no** `UploadedFile` class, MIME validation rule, size limit validation rule, or filename sanitization helper. Developers must validate `$_FILES['upload']['error']`, check MIME types via `finfo_file()`, enforce size limits, generate random filenames (never trust `$file['name']`), and resolve/verify destination paths with `realpath()`.
5. **Replacing Default `APP_KEY`**: Both [`.env.example`](../.env.example) and [`config/app.php`](../config/app.php) contain a placeholder `APP_KEY`. Always generate a unique 32-byte key for each deployment.
6. **Persistent Rate Limiting**: `RateLimiter::$storage` is a static PHP array in memory. In PHP-FPM/Apache CGI, each request spawns/resets process state or differs across workers; use Redis/DB/FileStore in `app/` for distributed/FPM rate limiting.
7. **HTTP Method Restrictions & Form Spoofing**: Remember `Request::capture()` allows `_method` in POST bodies and `X-HTTP-Method-Override` headers globally.

## 3. Potential Security Caveats & Recommendations

- **CSP `'unsafe-inline'`**: `SecureHeaders` currently defaults `Content-Security-Policy` to allow `'unsafe-inline'` for `script-src` and `style-src` (to support inline styles in `welcome.rocket.php`). Tighten CSP headers in production via custom middleware.
- **Query Builder Identifiers**: `Builder::wrapColumn()` and `wrapTable()` wrap column/table names in backticks without stripping backticks from user-supplied column names. **Never pass raw user input as column or table names** (e.g., validate `$request->query('sort_by')` against an allowlist before passing to `orderBy()`).
- **`Encrypter::decrypt()` & `FileStore::get()` Unserialization**: `Encrypter::decrypt()` authenticates ciphertext via AES-256-GCM AEAD tag before calling `unserialize($decrypted)`, preventing unauthenticated tampering, and `FileStore` uses PHP `serialize()`/`unserialize()` on disk cache files. Prefer `serialize: false` with JSON encoding when encrypting cross-service payloads.
- **SQLite Default Location & `.htaccess`**: Keep `database/database.sqlite` outside `public/` (it is in `database/`). Ensure `storage/public` only contains intentionally public files and never executes PHP scripts (configure web server to disable script execution in `public/storage`).
- **Validation Scope**: `Validator::validate()` returns only fields present in `$rules` that passed without errors, helping avoid unvalidated mass-assignment when passed to `Model::create($validated)` — provided `$fillable` is also properly restricted.
